# Интеграционные тесты плагина

Проверки для разработчиков плагина. Appium управляет отдельным Cordova-приложением с настоящим Yandex SDK и демоблоками. Плагин устанавливается из `npm pack`; подмен моста, SDK, ответов рекламы или событий нет.

## Запуск

Нужны Node.js 22.19+ в ветке 22.x или 24+, npm 10+, стандартное окружение Cordova. Android: JDK, Gradle, SDK и запущенный эмулятор с интернетом. iOS: macOS, Xcode с установленным runtime iPhone Simulator и CocoaPods.

```bash
npm install
npm ci --prefix tests/integration
npm run test:integration:setup -- android
npm run test:integration -- android

# На macOS:
npm run test:integration:setup -- ios
npm run test:integration -- ios
```

Драйверы Appium фиксированы по версии и устанавливаются в `.cache/integration/appium`. Глобальная установка Appium не меняется. Для Android используется единственное подключённое устройство; `INTEGRATION_UDID` выбирает конкретное. Для iOS используется запущенный iPhone Simulator либо запускается доступный; самостоятельно запущенный симулятор отключается в конце.

```bash
INTEGRATION_CASE='cold-start|invalid-id' npm run test:integration -- ios
```

Каждый сценарий перезапускает тестовое приложение `com.yandex.ads.integration`. Сценарии `cold-start-*` также удаляют и заново устанавливают только это приложение, проверяя первую загрузку без его накопленных данных SDK. `invalid-id-*` намеренно ожидают `FailedToLoad`; имя сценария и это ожидание выводятся на экран.

Только для отладки `INTEGRATION_APP=/absolute/path/to/fixture.apk` (либо `.app` для iOS) позволяет использовать готовую тестовую сборку. Путь есть в `environment.json`. После изменения плагина или тестового приложения нужна пересборка. В обычном прогоне и CI всегда собирается свежий npm-пакет. Appium принудительно устанавливает APK, даже если его versionCode не изменился.

## Сценарии

* Первая загрузка после чистой установки, init, consent до/после init, проверка аргументов JS.
* Отказ load/show/hide/reload до init с нативным `plugin_not_initialized`.
* Неверные ID: реальный `FailedToLoad`, JSON с причиной SDK, отсутствие события успеха; правильное событие ошибки AppOpen.
* Баннер: sticky/inline сверху/снизу, загрузка, показ, reload, hide, повторный цикл и восстановление WebView. Ожидания impression нет.
* Interstitial/Rewarded/AppOpen: загрузка и фактический показ по событию SDK, без ожидания impression, награды, переходов и закрытия рекламы.
* Уход в фон и возврат с pause/resume, последующая загрузка рекламы.
* Только Android: Feed preload/impression/hide и повторный показ; InStream загрузка/начало/завершение видео, cleanup и повторная загрузка.

Appium сохраняет скриншоты и XML нативного интерфейса. Полноэкранная реклама завершается перезапуском тестового приложения перед следующим сценарием. Контрольный прогон следует выполнять без ручных нажатий в симуляторе/эмуляторе.

Закрытие полноэкранной рекламы, награда Rewarded, клики по рекламным переходам, аппаратный D-pad, сторонние адаптеры медиации и поведение физических устройств требуют отдельных проверок. Feed/InStream на iOS плагином не поддерживаются.

## Отчёты и CI

`.artifacts/integration/<platform>/<run>/`: JSON/JUnit, build/Appium/native логи, события, скриншоты и нативные UI-деревья. Сгенерированные приложения остаются в `.cache/integration/apps` для диагностики.

Ошибки загрузки с корректными demo ID, отсутствующие callbacks/события, падения и таймауты делают прогон неуспешным. Они не превращаются в skips или passes, повторной загрузки для скрытия ошибки нет.

[Workflow](../../.github/workflows/integration.yml) запускает Android на API 35 и iOS на macOS 26. Запуск предусмотрен в pull request, при push в `master`/`main` и вручную. При ручном запуске можно указать regex имён сценариев. Артефакты сохраняются и при ошибке, секреты и production ad IDs не нужны.

`npm run test:install -- android|ios` отдельно проверяет установку, переустановку и нативную сборку с неизменным `config.xml` приложения; это не проверка работающей рекламы.
